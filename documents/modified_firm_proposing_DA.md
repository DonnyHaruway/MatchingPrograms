# 同僚の拒否ペアをランダムに解消する企業提案DA

`modified_firm_proposing_DA_algorithm` は二値の同僚選好（受容 `0`、拒否 `-INF`）を扱う。
全員を未マッチから開始し、次のA・Bを繰り返す。

## A：全企業の1ラウンドの提案

- ラウンド開始時に空きがある企業が、まだ提案していない最上位の候補者1人に提案する。
  定員が複数でも1ラウンドでの提案は1人。満員の企業は提案しない。
- 企業への選好と企業の個人への選好だけを使い、同僚への選好は無視する。
  負のスコアは受け入れ不可、`0` は受け入れ可能。
- 個人は、現在の仮マッチ先とそのラウンドの提案の中から最も好む企業を選ぶ。
  同順位なら現在の企業を維持する。現在の企業より高い同順位の提案が複数ある場合や、
  未マッチの個人への同順位の提案は、企業IDが最小のものを選ぶ。
  企業側の同順位の候補は個人ID順に提案する。
- 全企業の提案を解決してから仮マッチをまとめて更新する。
  このラウンドの移動によって空いた企業は、次のラウンドから再提案する。

## B：全拒否ペアの逐次処理

1. Aの結果から、同じ企業にいる個人の拒否ペアを全企業分集める。
   どちらか一方向でも同僚スコアが `-INF` なら拒否ペアとする。
2. ペアの一覧を一様ランダムな順にシャッフルし、順に処理する。
3. 既に片方がその企業から外されていれば、解決済みとしてスキップする。
4. 両方が残っているペアでは、片方を等確率（1/2）で選んで未マッチにする。
   選ばれた個人は**その企業に対して永久に削除**し、この実行中は再提案しない。
   他の企業に対しては削除しない。

削除だけでは新たな拒否ペアは生じないため、一覧の1回の走査でそのラウンドの全拒否ペアが解消する。
拒否ペアがない場合は削除せず、次のAへ進む。
削除後も他の仮マッチと全企業の提案履歴を維持し、DAを初期化しない。
個人が削除されても、他の企業が以前拒否された提案をやり直すことはない。

## 停止と返り値

空きがあり、まだ提案できる候補者を持つ企業がなくなった時点で停止する。
各企業は各個人に高々1回しか提案しないので、提案回数は高々 `n_firms * n_agents`。
空席が残っていても候補者を使い切れば停止する。

返り値は `Matching`。入力の選好は変更せず、削除の記録は実行内だけで保持する。
元の選好に対する universal-replacement 安定性は別途判定する。
ランダムな削除により、この安定性を満たさないマッチングを返す場合もある。

## 使用例

```cpp
// ms に選好と定員を設定済みとする。
Matching matching = ms.run_algorithm("modified_firm_propose_DA", 42);
bool stable = matching.is_universal_replacement_stable(
    ms.get_agent_prefs(), ms.get_firm_prefs(),
    ms.get_agent_col_prefs(), ms.get_firm_capacities());
```

直接呼び出す場合：

```cpp
Matching matching = modified_firm_proposing_DA_algorithm(
    n_agents, n_firms, firm_capacities,
    agent_prefs, firm_prefs, agent_col_prefs, 42);
```

seedを省略すると `std::random_device` から取得する。
同じ入力・seed・実行環境では同じ結果になる。
