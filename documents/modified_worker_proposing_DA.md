# 同僚の拒否ペアをランダムに解消する個人提案DA

`modified_worker_proposing_DA_algorithm` は二値の同僚選好（受容 `0`、拒否 `-INF`）を扱う。
全員を未マッチから開始し、次のA・Bを繰り返す。

## A：全個人の1ラウンドの提案

- ラウンド開始時に未マッチの個人が、まだ提案していない最上位の企業1社に提案する。
  仮マッチ中の個人は新たな提案をしない。個人の同順位の企業は企業ID順に選ぶ。
- 企業と個人の相互の選好だけを使い、同僚への選好は無視する。
  双方の負のスコアは受け入れ不可、`0` は受け入れ可能。
- 各企業は、現在の仮マッチとそのラウンドの全新規提案から、
  企業にとって好ましい順に定員まで仮受諾する。定員0の企業は全提案を拒否する。
  同順位なら既存の仮マッチを優先し、そのほかの同順位は個人ID順に選ぶ。
- 全企業の仮受諾・拒否を決めてからBへ進む。
  拒否された個人は、次のラウンドから次の未提案の企業へ提案する。
  同じラウンド中に再提案しない。

## B：全拒否ペアの逐次処理

[企業提案版](modified_firm_proposing_DA.md) と同じ処理を使う。

1. Aの結果から、同じ企業にいる個人の拒否ペアを全企業分集める。
   どちらか一方向でも同僚スコアが `-INF` なら拒否ペアとする。
2. 全ペアを一様ランダムな順にシャッフルし、順に処理する。
3. 既に片方がその企業から外されていれば、解決済みとしてスキップする。
4. 両方が残っているペアでは、片方を等確率（1/2）で選んで未マッチにする。
   選ばれた個人は**その企業の候補から永久に削除**する。

削除はその企業に限る。他の企業の候補からは削除しない。
選ばれた個人は次のラウンドから次の未提案の企業へ進み、同じ企業には再提案しない。
他の仮マッチと個人の提案履歴は保持し、DAを初期化しない。

削除だけでは新たな拒否ペアは生じないため、一覧の1回の走査で全拒否ペアが解消する。
拒否ペアがなければ何も削除せず、次のAへ進む。

## 停止と返り値

未マッチで、まだ提案できる企業を持つ個人がいなくなった時点で停止する。
各個人は各企業に高々1回しか提案しないので、提案回数は高々 `n_agents * n_firms`。
未マッチや空席が残っていても候補を使い切れば停止する。

返り値は `Matching`。入力の選好は変更せず、削除の記録は実行内だけで保持する。
元の選好に対する universal-replacement 安定性は別途判定する。
ランダムな削除により、この安定性を満たさないマッチングを返す場合もある。

## 使用例

```cpp
// ms に選好と定員を設定済みとする。
Matching matching = ms.run_algorithm("modified_worker_propose_DA", 42);
bool stable = matching.is_universal_replacement_stable(
    ms.get_agent_prefs(), ms.get_firm_prefs(),
    ms.get_agent_col_prefs(), ms.get_firm_capacities());
```

直接呼び出す場合：

```cpp
Matching matching = modified_worker_proposing_DA_algorithm(
    n_agents, n_firms, firm_capacities,
    agent_prefs, firm_prefs, agent_col_prefs, 42);
```

seedを省略すると `std::random_device` から取得する。
同じ入力・seed・実行環境では同じ結果になる。
