# 企業2・個人6・定員各2：全分岐失敗と2段階の干渉の可否

2026-11-04。前回の企業2・個人5の検査を、個人6人へ拡張した。

**今回の設定では、全分岐で元問題のUR安定を導出しない例は0件だった。** すべての入力で、少なくとも1本の有効な削除経路が元問題でUR安定な終点に到達することを、独立した別実装でも確認した。

そのため、「子の削除が祖先の削除理由に干渉する2段階の経路」と「全分岐でUR安定を導出しない」という両条件を満たす例も、この設定では構成できない。探索の深さは制限せずに検査している。2階層より深く探索する場合にも、全分岐失敗の入力はなかった。

## 対象と結果

企業数2、個人数6、各企業の容量2。個人告白型Recursive DAを使用する。企業・個人の選好は厳密で、受入可能な企業は未マッチより好ましい。禁止ペアは企業によらないbinary同僚拒否である。

| 選好の範囲 | 正規化した選好数 | 禁止ペア集合数 | 全組合せ数 | 全分岐失敗 |
|---|---:|---:|---:|---:|
| 全員相互に受入可能 | 46,080 | 32,768 | 1,509,949,440 | **0** |
| 受入不可も許す | 11,250,000 | 32,768 | 368,640,000,000 | **0** |

前者は後者に含まれる。数は正規化した選好と禁止集合の組合せ数で、無関係な拒否辺などによる意味的な重複までさらに除いた市場の同型類数ではない。

これは上の有限範囲についての計算による確認である。企業数・個人数・定員・無差別・同僚制約の形式を変えた場合の一般的不可能性までは主張しない。

## 入力を網羅する方法

片側だけが拒否する企業・個人の組は、相互の受入不可にまとめられる。受入不可を個人側のリストへ移し、企業側の順位を完全な厳密順位へ拡張する。残る相対順位・未マッチとの比較を保つので、DAの最終割当と個人合理的な割当でのUR逸脱の可否は変わらない。

個人名をf1の順位に沿って付け替えて、f1の順位をw1>w2>…>w6に固定する。f2の順位は6!=720通り。各個人の受入リストは次の5通りである。

1. f1>f2>未マッチ
2. f2>f1>未マッチ
3. f1だけ受入可能
4. f2だけ受入可能
5. 両企業とも受入不可

したがって受入不可を許す範囲は720×5⁶=11,250,000通り。全員受入可能なら720×2⁶=46,080通りとなる。

6人の異なる2人組は15組あるため、共通禁止集合は2¹⁵=32,768通り。すべての個人が受入可能な前者の検査も別に実行しており、無関係な6人目を追加した入力だけを調べたものではない。

## 安定経路による全禁止集合の被覆

前回の問題だった「経路ごとに代表の禁止集合だけを選ぶ」処理は使わない。

各選好について、元問題でUR安定な終点に到達する有効な削除経路を保存する。その経路が実行でき、終点がUR安定になる禁止集合を、32,768ビットの集合として厳密に計算する。これらの和集合が全32,768集合を覆うことを確認する。

経路が固定されると、条件は次のとおりである。

- 各削除で理由として選んだ同居ペアは、禁止集合に含まれる。
- 終点で同じ企業に所属する2人は、禁止ペアではない。
- 元の企業・個人の選好だけを見れば逸脱可能な各組について、同僚の拒否がuniversal replacementまたは空席への追加逸脱を妨げる。

各DAは過去の削除だけを累積し、全員未マッチ・提案履歴なしから再実行する。削除経路の途中で選ぶペアが現に同居していることも、全経路で検査する。

同じ経路が複数の禁止集合で成立する場合は、それらをまとめて証明する。代表の1集合からほかの集合へ結果を推測する方式ではない。

全員受入可能の範囲では1,763,788本、受入不可を許す範囲では119,635,082本の安定経路を保存し、それぞれで対象の全入力を覆った。

「全分岐失敗」の否定には安定経路が1本あれば十分である。探索では安定経路を見つけた後、その入力の残りの枝を列挙し続ける必要はない。見つからない場合は全削除枝を検査する設計だが、今回そのような入力はなかった。

## 独立検算

探索側と検算側は別の実装である。

- **探索側**：逐次提案のDA、個人集合のビット表現、削除集合を状態とする探索。
- **検算側**：ラウンドごとの同時提案DA、在籍者の配列表現。保存された削除列を読み、独立にDAを再実行し、有効な禁止集合の被覆と終点の元問題でのUR安定性を確認する。探索側のソースはインクルードしない。

検算側は全選好IDが順番どおり過不足なくあること、全禁止集合が被覆されること、証明データ末尾に余分な入力がないことも確認する。

| 検算範囲 | 検算した選好数 | 証明が覆う入力数 | 結果 |
|---|---:|---:|---|
| 全員受入可能 | 46,080 | 1,509,949,440 | 全件通過 |
| 受入不可を許す | 11,250,000 | 368,640,000,000 | 全件通過 |

加えて、選択した12入力の全分岐木を、既存リポジトリのC++本体と既存の独立Pythonモデルで照合した。全92ノード・57終点の割当、削除履歴、禁止ペア、元問題/削除後のUR判定が一致した。

証明はXZで圧縮し、解凍後のバイト列のSHA-256が元データと一致することも確認した。検算後の非圧縮の重複ファイルは削除している。

証明ファイルの先頭は`URG2`、続いて個人数6とリストのbase（2または5）が各1バイト。各選好のレコードは選好ID（u32）、経路数（u16）、全分岐失敗の禁止集合数（u16）で始まる。今回の失敗数はすべて0。各経路は削除数（u8）と削除列（6バイト）であり、整数はlittle-endian。

削除列は企業番号×6＋個人番号（ともに0始まり）を4ビットずつ格納し、最初の削除が最下位にある。選好IDはf2の順列の辞書順番号×base⁶＋個人リストコード。個人リストの型は上記5通りの順、コードの最下位桁がw1である。

## 再実行

このディレクトリで実行する。

```sh
c++ -std=c++17 -O3 -Wall -Wextra search.cpp -o /tmp/ancestor_2x6_search
/tmp/ancestor_2x6_search complete results/complete --stop-target
/tmp/ancestor_2x6_search incomplete results/incomplete --stop-target
c++ -std=c++17 -O3 -Wall -Wextra verify_certificates.cpp -o /tmp/ancestor_2x6_verify
/tmp/ancestor_2x6_verify results/complete_graph_cover.bin results/complete_independent_verification.json
/tmp/ancestor_2x6_verify results/incomplete_graph_cover.bin results/incomplete_independent_verification.json
python3 package_certificates.py --remove-raw
```

`--stop-target`は、全分岐失敗かつ深さ2以内で、祖先の削除を戻す比較まで満たす満員終点の干渉例が見つかった場合に停止する指定。今回そのような入力はなく、両モードとも予定範囲を最後まで完了した。結果JSONの`completed_requested_range`は両方とも`true`である。

保存済み証明だけを再検算する場合は、例えば次のように展開する。入力生成用の探索は再実行不要である。

```sh
python3 package_certificates.py --extract results/complete_graph_cover.bin.xz /tmp/ancestor_2x6_complete.bin
/tmp/ancestor_2x6_verify /tmp/ancestor_2x6_complete.bin /tmp/ancestor_2x6_complete_check.json
```

受入不可を許す範囲の非圧縮証明は約927MBになるため、展開先の空き容量を確保する。

5人の場合の結果は [前回の全入力検査](../ancestor_interference_2x5/all_graphs_recheck/README.md) に保存しており、今回変更していない。
