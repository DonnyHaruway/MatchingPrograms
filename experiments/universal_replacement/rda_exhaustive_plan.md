# 企業告白型RDAの全列挙：条件整理と入力件数

2026-11-16時点の指定条件と見積もり。新条件でのRDA本実験は未実行。
新条件への対応は[新方式の実行手順と出力形式](rda_three_stabilities.md)を参照。
従来の引数だけで起動した場合は旧方式を使う。

## 実験条件

ここでは `n` を企業数、`m` を個人数とする。

| (n,m) | 定員ベクトル | 禁止ペア数K |
|---|---|---|
| (2,2) | [1,2] | 1 |
| (2,3) | [1,2] | 1,2 |
| (3,4) | [1,1,2] | 1,2,3 |
| (3,5) | [1,2,2] | 1,2,3,4 |

- 個人は全企業と未マッチ、企業は全個人と空席を含む厳密順位を持つ。
  未マッチ・空席より下の順位も保持する。同順位はない。
- スコアは「未マッチ・空席の順位 − 相手の順位」。未マッチ・空席は0。
- 禁止ペアは全企業で共通の個人間の無向関係。1組を1件と数え、全配置を列挙する。
  入力行列の表現は両方向を `-INF`、その他を0に統一する。
  現実装の違反検出とURのfeasibilityは、片方向だけが `-INF` でも拒否として扱う。
- 名前の付け替えは選好・禁止ペア・定員すべてに反映する。
  代表入力数と、同値類の大きさを掛けた元のラベル付き入力数を併記する。
- 企業告白型RDAを使い、内部では全違反ペアと両削除対象を愚直に探索する。
  安定解発見による打ち切り、枝刈り、状態統合を行わない。
- 全葉について、削除前の元の入力に対するUR / weak / stabilityを独立判定する。
  各定義で `all_stable` / `mixed` / `none_stable` に分類し、
  経路数と重複を除いた終点マッチング数を区別する。
- URには空席への追加ブロッキングも含む。
- RDAとは独立に定員内の割当を列挙し、3種類それぞれの安定解の存在を調べる。
  `none_stable` と「市場に安定解が存在しない」を区別する。

## 対称性による削減の根拠

定員ベクトルを上表の順序で固定した断面で数える。
個人名の置換は `m!` 通り、企業名の置換でこの断面を保つものは
同一定員企業の置換だけであり、その数を `h` とする。
異なる定員の企業の交換も定員ごと交換すれば同じ市場を表すが、断面の外に移る。
断面内でさらに `n!` で割ることはできない。

今回の4市場では定員が固有の企業が必ず1社以上ある。その企業は自己同型で固定される。
その企業の全個人に対する厳密順位から、すべての個人名も固定される。
さらに個人の全企業に対する厳密順位から、すべての企業名も固定される。
したがって非自明な自己同型はなく、各同値類の大きさは一律 `m! h`。
禁止グラフだけに対称性があっても、この結論は変わらない。

禁止ペア数Kごとの入力数は次式で正確に計算できる。

```
元の入力数 = ((n+1)!)^m × ((m+1)!)^n × C(C(m,2), K)
代表入力数 = 元の入力数 / (m! × h)
```

直接代表を生成する際は、定員が固有の企業を1社選び、その順位に現れる
個人名の順をw1,w2,...に固定する。空席の位置m+1通りはすべて残す。
同一定員の企業が2社ある市場では、w1の順位でその2社の順序を固定する。
禁止ペアはその正規化後の名前に対して全配置を列挙する。
この手順なら元の全入力を生成してから重複除去する必要はない。

件数自体は両方保存する。異なる市場をまとめた割合では重みの違いに注意する。

## 安定解の存在判定と所要時間の尺度

未マッチを許して定員以内に収めた全割当の数は順に8、19、115、456。
これは禁止ペアや受け入れ不可による除外前の件数。
各代表に対してこの候補をすべて生成すると、候補割当数の合計は順に
5,184、2,363,904、56,315,658,240,000、2,174,042,492,633,088,000となる。
候補数を3倍したものが、除外・打ち切りなしで3判定を全候補に行う場合の判定回数。
禁止ペアや個人合理性による事前除外、存在だけが目的の場合の発見後の打ち切りにより減らせる。
RDA内部の探索はこれらとは別であり、全分岐を探索する。

仮に全処理込みで毎秒100万代表を処理できるとしても、(3,4)は約5.67日、
(3,5)は約151年を要する。これは仮定した処理速度による換算であり、実測値ではない。
RDAのDA呼び出し回数・葉数は入力依存なので、入力数だけから実時間は確定しない。
